# incidentctl — инструкция пользователя

Приложение создаёт учебную Linux VM, вносит неисправность и открывает терминал
для её исправления. Ansible проверяет результат, а необязательный LLM-анализ
помогает разобрать ваши действия.

## Что нужно

- Архив для вашей системы: Windows amd64, Linux amd64, macOS amd64 (Intel)
  или macOS arm64 (Apple Silicon).
- Установленные **Git** и **OpenSSH**, доступные в терминале: `git --version`, `ssh -V`.
- Браузер, доступ к серверу учебных VM и выданный администратором токен.

Go, Python, Ansible и отдельная установка audit-agent на вашем компьютере
не требуются. Необходимые компоненты внутри VM приложение устанавливает само.

## Первый запуск

Распакуйте архив и откройте терминал **в распакованной папке**. В ней находятся
приложение, эта инструкция и `incidentctl.example.json`.

Windows, PowerShell:

```powershell
Copy-Item incidentctl.example.json incidentctl.json
.\incidentctl.exe -config incidentctl.json
```

Linux/macOS:

```bash
cp incidentctl.example.json incidentctl.json
./incidentctl -config incidentctl.json
```

Конфигурацию достаточно скопировать один раз. Для следующих запусков нужна
только вторая команда. Приложение запускается из терминала, на Windows —
не двойным щелчком по `.exe`.

В TUI нажмите **`a`**, вставьте токен VM API и нажмите Enter.
Выберите упражнение через Enter и нажмите **`s`** для подготовки VM.
Когда подготовка завершится, приложение откроет веб-терминал в браузере.
Исправьте неисправность и нажмите **`v`** в TUI для проверки.

## Конфигурация

Редактируйте `incidentctl.json`. Основные поля:

| Поле | Что указать |
| --- | --- |
| `vm_service.base_url` | Адрес VM API, полученный у администратора. Проверьте адрес из примера. |
| `vm_service.image_id` | Образ учебной VM, согласованный с администратором. |
| `vm_service.profile` | Необязательный профиль ресурсов. Если поля нет, используется профиль сервера. |
| `vm_service.ttl_seconds` | Время жизни VM в секундах; сервер может ограничить значение. |
| `exercise_repository.repository` | Git-репозиторий заданий. В примере настроен HTTPS. |
| `exercise_repository.ref` | Ветка заданий, по умолчанию в примере `master`. |
| `audit.llm.enabled` | Включить LLM-анализ после успешной проверки. По умолчанию выключен. |
| `audit.llm_reports_dir` | Папка отчётов LLM относительно конфигурации. |

Остальные значения можно оставить из примера. Токен VM API вводится через TUI
и сохраняется автоматически в пользовательской папке настроек ОС.

### LLM-анализ, по желанию

В `audit.llm` установите `enabled: true` и задайте собственный DeepSeek API key
через переменную окружения **перед запуском приложения**:

```powershell
$env:DEEPSEEK_API_KEY = "ваш-ключ"
.\incidentctl.exe -config incidentctl.json
```

```bash
export DEEPSEEK_API_KEY='ваш-ключ'
./incidentctl -config incidentctl.json
```

`base_url` и `model` в секции `audit.llm` определяют сервис и модель.
Ключ остаётся на вашем компьютере. Результат упражнения определяет Ansible;
ошибка LLM не отменяет успешную проверку.

### Подключение через прокси

Если API и SSH доступны через локальный HTTP-прокси:

```powershell
$env:HTTPS_PROXY = "http://127.0.0.1:10809"
$env:INCIDENTCTL_SSH_PROXY = $env:HTTPS_PROXY
.\incidentctl.exe -config incidentctl.json
```

```bash
export HTTPS_PROXY=http://127.0.0.1:10809
export INCIDENTCTL_SSH_PROXY="$HTTPS_PROXY"
./incidentctl -config incidentctl.json
```

Замените порт на порт вашего прокси. `HTTPS_PROXY` задаёт маршрут HTTP API,
`INCIDENTCTL_SSH_PROXY` — SSH к VM. Для SSH также поддерживается
`socks5://127.0.0.1:1080`, без авторизации на прокси. Прокси должен разрешать
соединения на SSH-порты, выданные сервером. Дополнительный `nc` не нужен.

Чтобы LLM тоже использовал переменные прокси, задайте
`audit.llm.proxy_mode: "environment"`; значение `direct` включает прямой запрос.

## Управление

| Клавиша | Действие |
| --- | --- |
| `a` | Ввести или заменить токен VM API. |
| `s` | Начать решение выбранного упражнения. |
| `d` / `t` | Описание / подсказки на экране решения. |
| `v` | Проверить решение; запись останавливается перед проверкой и включается снова после неё. |
| `p` | Повторить этап, когда TUI предлагает повтор, включая ожидание веб-терминала. |
| `o` / `c` | Открыть отдельный SSH-терминал / показать команду SSH. |
| `x` | Вернуться из решения к списку упражнений. |
| `q` | Выйти из TUI. При обычном завершении клиент удаляет **все VM вашей учётной записи** через API. |

`verification` сразу после внесения инцидента должна обнаружить неисправность:
её ненулевой код в этом месте ожидаем. Оценка вашего решения запускается по `v`.
Если Nexterm пока не готов, можно повторить открытие по `p` или работать через `o`.

## Отчёты и обновление

Из папки запуска приложение сохраняет данные проверок в `analysis/`.
При включённом LLM итоговый разбор находится в
`llm-reports/<упражнение>/<номер>/analysis.md`, если путь не изменён в конфигурации.
Ключи, токен и `incidentctl.json` не нужно отправлять вместе с отчётом об ошибке.

Для обновления завершите приложение, распакуйте новую версию и перенесите
свой `incidentctl.json`; повторно копировать пример поверх своего файла не нужно.
Оба варианта audit-agent уже включены в приложение и обновляются вместе с ним.

Версия приложения и встроенного агента:

```powershell
.\incidentctl.exe --version
```

```bash
./incidentctl --version
```

При обращении за помощью приложите вывод версии, название упражнения и текст
ошибки из TUI. Ошибки `banner exchange` означают сбой соединения SSH до команды;
проверьте прокси и доступность VM-хоста. Если автоматические попытки исчерпаны
и TUI предлагает `p`, можно повторить незапущенный этап на той же VM.
