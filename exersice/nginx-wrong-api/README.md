# Инцидент «Не тот адрес»

## Ситуация

Python-приложение работает в Docker-контейнере за Nginx. Для каждого HTTP-запроса приложение возвращает значение заголовка `Host` в JSON:

```json
{"host":"api.example.test"}
```

После изменения инфраструктуры приложение стало возвращать внутренний адрес вместо адреса, который передал клиент.

## Топология

```text
клиент → Nginx :80 → echo-server :8080 (Docker)
```

Nginx доступен на порту `80`. Echo-server привязан только к `127.0.0.1:8080` и напрямую извне недоступен.

## Задача

Найдите причину, по которой значение `Host` изменяется на пути до приложения, и восстановите передачу исходного значения. Не меняйте контракт echo-server.

## Критерий готовности

Команда проверки должна завершиться успешно:

```bash
bin/incidentctl verify nginx-wrong-api
```

Проверка отправляет запрос с заранее заданным `Host` и сравнивает его с JSON-ответом приложения.

## Управление сценарием

```bash
bin/incidentctl infra nginx-wrong-api
bin/incidentctl incident nginx-wrong-api
bin/incidentctl verify nginx-wrong-api
```

После `incident` проверка должна падать, пока проблема не исправлена.
